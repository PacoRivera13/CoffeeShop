# Decisions
- Local verification uses LocalDB; integration tests use Testcontainers (SQL Server, MinIO) and need Docker running.
- IDs are `int` identity columns, with fixed values in the seed.
- `asOf` accepts ISO 8601 only and is read as UTC when it has no offset; it defaults to the current time.
- A SKU with no effective price returns 404 with its own title, distinct from an unknown SKU.
- `DomainExceptionHandler` maps domain errors centrally: no effective price is 404, any other is 422.
- Prices are insert-only in `SaveChanges` and in a database trigger that rejects UPDATE and DELETE.
- Inventory is not seeded in this milestone; it was not part of the requested seed.
- Seed prices are in EUR and start on 2026-01-01; SKU 1 has extra rows to show price history and a future change.
- Migrations are applied explicitly with `dotnet ef`, never at startup.
- Pinned System.Security.Cryptography.Pkcs 10.0.14 directly: the 9.0.11 pulled in by EF Core SqlServer has known CVEs.
- SQL Server tests use a temporary LocalDB database on Windows; other platforms need `COFFEESHOP_TEST_SQLSERVER` or they report as skipped.
- API docs use the official `Microsoft.AspNetCore.OpenApi` generator with Swashbuckle SwaggerUI, and are exposed in Development only.
- Root `openapi.json` is a snapshot without `servers`, kept in sync by a test; regenerate with `UPDATE_OPENAPI=1 dotnet test --filter Committed_document`.
- `IdentityUser` uses string keys; `sub` is the Identity user id and `UserName` equals the email, whose unique index resolves concurrent registrations as 409.
- Roles are seeded by migration; the Admin user has no `Customer` row and an existing Admin keeps its password when the seed runs again.
- Passwords follow Identity defaults with a minimum length of 8.
- `Jwt__Key` is empty in `.env.example` so an unedited copy fails at startup; ASP.NET does not read `.env`, so use env vars or user-secrets.
- `dotnet ef` uses `CoffeeShopDbContextFactory` so migrations work without JWT settings.
- `GET /auth/me` is the protected endpoint; `AdminOnly` has no endpoint yet and is tested through `IAuthorizationService`.
- Login has no lockout or rate limiting yet, and an unknown email skips password hashing, so response time can reveal which emails exist.
- `POST /prices` answers 400 for missing or malformed fields, including amount and currency, and 422 only for a past `effectiveFrom`.
- Price amounts must be positive with at most 2 decimals and 16 integer digits; a CHECK enforces `Amount > 0` in the database.
- Currencies are validated against a fixed ISO 4217 list in Domain, because an append-only typo could not be corrected.
- `effectiveFrom` uses the same parser as `asOf`, so a value without an offset is UTC, not server local time.
- `isCurrent` resolves with the current time, like `GET /skus/{id}/price` without `asOf`.
- A price dated today at an hour already past is accepted and changes the price from that hour; existing orders keep their frozen price.
- Registration takes an `sp_getapplock` per normalized email inside its transaction, because concurrent Identity inserts for one email deadlocked and returned 500.
- Orders validate the raw request (1-20 lines, qty 1-50) and also cap merged quantities at 50 per SKU.
- A SKU without a current price makes `POST /orders` answer 422; mixed currencies are a domain error, also 422.
- An Idempotency-Key (max 100 chars) replays the original order even if the new body differs; replay answers 200.
- Stock is reserved per product in ascending product id so concurrent orders cannot deadlock on inventory rows.
- `EnableRetryOnFailure` is off; order writes still run inside the execution strategy so enabling it later is safe.
- Pay and cancel use a row version on Order and retry up to 3 times on a concurrent change, so concurrent cancels release stock once.
- Inventory is seeded by migration SQL for products without a row, with a Restock movement, so stock always equals the sum of movements.
- `InventoryMovements` are insert-only, enforced in `SaveChanges` and by a database trigger, like prices.
- `POST /orders` needs the Customer role (`CustomerOnly` policy); `GET /orders/{id}` also allows Admin; pay and cancel are owner-only.
- Code review runs before every push (one review per milestone), not after a fixed count of changes; a push is the natural checkpoint.
- Outbox claims set NextAttemptAt to now + 5 min (a lease) in one UPDLOCK/READPAST statement; a crashed dispatcher's claims reappear after it.
- Retry backoff is 2s * 2^(attempts-1), capped at 5 min; a message is Failed once Attempts reaches Outbox:MaxAttempts.
- Messages travel as an envelope with a stable type name ("OrderCreated") and a JSON payload, so an SQS adapter can carry them unchanged.
- Each handler runs in its own transaction and writes its ProcessedMessage row first, so a concurrent duplicate waits and then skips.
- External side effects such as emails stay at-least-once: a crash after the handler but before commit runs it again.
- No outbox row is written for no-ops (paying a paid order, cancelling a cancelled one, idempotent replays).
- Done outbox rows and ProcessedMessage markers are kept for now; a retention job is a follow-up once volumes matter.
- Stock is reserved synchronously in the order transaction with a conditional UPDATE, not later from the outbox: a 201 means the grams are held, so there is no overselling and no compensation flow.
- The database runs with READ_COMMITTED_SNAPSHOT: locking reads made concurrent sign-ups deadlock on the small Identity tables; registration also retries a deadlock victim up to 5 times.
- API tests use a dedicated CoffeeShopTests database in the container instead of master, where READ_COMMITTED_SNAPSHOT cannot be enabled.
- Restocking a product without an inventory row creates it; a restock that would overflow the stock column answers 422.
- `GET /admin/inventory` is not paged: it lists every product, a small catalogue; movements are paged.
- Deadlock retries cover registration only; other write paths rely on snapshot reads, and enabling EnableRetryOnFailure everywhere is a follow-up (explicit test transactions would need the strategy too).
- Docker Hub and Quay no longer serve MinIO images; compose and tests pin Chainguard's maintained MinIO build by digest.
- S3FileStorage uses one client for I/O (internal endpoint) and one only for presigning (public endpoint), with SDK v4 checksums set to WHEN_REQUIRED for MinIO compatibility.
- Storage settings are validated at startup like JWT; Development defaults point at localhost:9000, keys come from env vars or user-secrets.
- Handlers marked IRunsOutsideTransaction (InvoiceHandler) run without the bus transaction and record ProcessedMessage after success, so uploads never hold database locks.
- The invoice number is drawn from the SQL sequence before rendering because it is printed on the PDF; failed attempts leave gaps.
- A concurrent duplicate invoice delivery re-uploads the PDF with the winning row's number, so the stored file always matches the row.
- Compose does not run migrations; apply them with dotnet ef against the compose SQL Server before starting api.
- The invoice handler skips orders cancelled before OrderPaid was delivered; Development still requires MinIO at startup (fail fast, like JWT).
- Invoices are demo receipts ("Demo receipt - not fiscally valid"): no taxes, no fiscal numbering guarantees (sequence gaps allowed), not legal invoices.
- `GET /orders/{id}/invoice`: an existing invoice is always served (200), even after cancel; no invoice yet answers 202 with Retry-After for paid or later orders and 409 for Pending or Cancelled ones, which will never get one.
- A presigned URL's path necessarily contains the bucket and object key; API fields never expose them or the internal endpoint.
- MXN is the default currency: a migration appends MXN prices (1 EUR = 20 MXN, rounded) effective at migration time, plus an MXN twin 100 ns after each scheduled EUR change; EUR history and past orders stay untouched. All tests use MXN.
- Invoice numbers can jump (e.g. to 51) after SQL Server restarts, because sequences cache values; gaps are accepted.
- `GET /orders/{id}/invoice` answers 202 only while the order's OrderPaid message is pending; a paid order whose event is Done or Failed without an invoice answers 409 "Invoice unavailable".
- POST /prices only accepts the store currency (Pricing:Currency, default MXN, validated at startup); a ready invoice whose PDF is missing from storage answers 409 instead of a broken URL.
- Web dev proxy sends /api to http://localhost:5121 (the API's http launch profile), not 5000; the nginx web container is deferred to a later milestone.
- The Angular client is generated from openapi.json with ng-openapi-gen into web/src/app/api and committed; regenerate with `npm run gen:api`.
- Playwright browsers are installed into web/node_modules (PLAYWRIGHT_BROWSERS_PATH=0, set by the npm scripts through cross-env).
- `/` and `/admin` are placeholder pages until the catalogue and admin UI milestones; they exist to exercise guards and role redirects.
- Breakpoints live only in _breakpoints.scss; TypeScript reads them through CSS custom properties to build CDK BreakpointObserver queries.
- The drawer uses mat-button links instead of mat-nav-list, whose module pulls @angular/forms into the initial bundle (about 78 kB).
- npm 11 install scripts stay blocked (esbuild, lmdb, msgpackr-extract, @parcel/watcher); their prebuilt binaries are enough.
- index.html carries a small inline script that applies the saved theme before first paint; a future Content-Security-Policy must allow it by hash.
- The web session ends on a timer at the token expiry; register no longer signs in on its own, the page does, and a failed sign-in after registering sends the user to /login.
- Milestone 5b needed no API change: GET /products already returns SKU ids, and the 409 stock problem carries productId, requiredG and availableG.
- The catalogue accepts an optional ?asOf= query parameter and forwards it to GET /skus/{id}/price, to preview scheduled prices.
- The cart lives in sessionStorage (roastery.cart), allows 1-50 units per SKU like the API, and is emptied when the session ends.
- One Idempotency-Key per checkout attempt: retries of the same cart reuse it; any change to the cart starts a new attempt with a new key.
- Order lines and stock errors carry ids only; the web resolves product names from the catalogue (falling back to "SKU n").
- The invoice opens with window.open(url, '_blank', 'noopener') and also stays available as a link, since a popup after polling may be blocked.
- Initial bundle warning budget is 550 kB (error stays at 1 MB): esbuild hoists framework modules shared with the lazy pages into main.
- Docker Compose now serves the web app on :8080 (nginx, /api proxied like the dev proxy); the API moved to host port 8081.
- The admin price form limits effectiveFrom to today in UTC (the API's rule), so late-evening admins west of UTC cannot pick their local today.
- Price history is sorted newest first in the client; the API returns it in no guaranteed order.
- "Low stock" means below LOW_STOCK_THRESHOLD_G = 2000 g (web/src/app/features/admin/admin-rules.ts).
- The admin menu (MatMenu) is loaded with @defer only for admins, keeping it out of the initial bundle.
- The @full purchase spec runs only through `npm run e2e:full` (project "full", no dev server); `npm run e2e` runs desktop and mobile only.
- Full-stack admin credentials come from E2E_ADMIN_EMAIL / E2E_ADMIN_PASSWORD, which must match the stack's Admin__Email / Admin__Password.
- The demo seed keeps the migration HasData catalogue, so a dev database lists 9 products (3 legacy, 6 demo, two named Yirgacheffe).
- scripts/dev runs the API on :5121 to match proxy.conf.json and launchSettings; the compose service is `sqlserver`, not `db`.
- Roast is a free string, so demo roasts (including "Medium-Dark") are stored as given; no mapping was needed.
- The demo seeder backdates orders, restocks and outbox rows by constructing OrderService/InventoryService with a fixed TimeProvider.
- scripts/dev ignores Jwt__Key from .env (it would override user-secrets) and generates its own key into user-secrets once.
- Demo-seeder tests use a second database (CoffeeShopDemo) on the shared SQL Server container, so demo rows never reach other tests.
- Dev__ClockOffsetDays shifts only the application clock; JwtTokenIssuer, S3 presigning and log timestamps take the keyed real clock, because JwtBearer and S3 check tokens and URLs against real time.
- scripts/dev-infra writes the API environment to .vscode/api.env (git-ignored by .vscode/*, LF endings) for the VS Code launch config; Visual Studio/Rider users copy it into user-secrets.
- GET /health returns {status, checks:[{name, status, durationMs}]} only (503 when any check fails), never exception text; /health/live checks the process alone.
- GET /admin/outbox lists newest OccurredAt first; status is optional and case-insensitive; pageSize is capped at 100.
- The Development console uses a custom "correlation" formatter: time, level, short category, [correlation id], message; other scopes are dropped.
- api.http uses REST Client request-variable syntax (also Visual Studio); httpyac does not support it, so it was verified by replaying the same requests with a script.
- The catalogue page is public (GET /products was already anonymous); anonymous cards show "Sign in to buy" linking to /login?returnUrl=/, while cart, orders and admin stay behind authGuard.
- The full-stack purchase spec locates the product by position (first in id order), since product names are not unique once the demo seed runs.
