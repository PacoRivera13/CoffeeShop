# Decisions
- Local verification uses LocalDB; auth tests use Testcontainers and need Docker running; `docker-compose.yml` has not been run.
- IDs are `int` identity columns, with fixed values in the seed.
- `asOf` accepts ISO 8601 only and is read as UTC when it has no offset; it defaults to the current time.
- A SKU with no effective price returns 404 with its own title, distinct from an unknown SKU.
- `DomainExceptionHandler` maps domain errors centrally: no effective price is 404, any other is 422.
- Prices are insert-only in `SaveChanges` and in a database trigger that rejects UPDATE and DELETE.
- Inventory is not seeded in this milestone; it was not part of the requested seed.
- Seed prices are in EUR and start on 2026-01-01; SKU 1 has extra rows to show price history and a future change.
- Migrations are applied explicitly with `dotnet ef`, never at startup.
- Pinned System.Security.Cryptography.Pkcs 10.0.14 directly: the 9.0.11 pulled in by EF Core SqlServer has known CVEs.
- SQL Server tests use a temporary LocalDB database on Windows; other platforms need `COFFEESHOP_TEST_SQLSERVER` or they report as skipped.
- API docs use the official `Microsoft.AspNetCore.OpenApi` generator with Swashbuckle SwaggerUI, and are exposed in Development only.
- Root `openapi.json` is a snapshot without `servers`, kept in sync by a test; regenerate with `UPDATE_OPENAPI=1 dotnet test --filter Committed_document`.
- `IdentityUser` uses string keys; `sub` is the Identity user id and `UserName` equals the email, whose unique index resolves concurrent registrations as 409.
- Roles are seeded by migration; the Admin user has no `Customer` row and an existing Admin keeps its password when the seed runs again.
- Passwords follow Identity defaults with a minimum length of 8.
- `Jwt__Key` is empty in `.env.example` so an unedited copy fails at startup; ASP.NET does not read `.env`, so use env vars or user-secrets.
- `dotnet ef` uses `CoffeeShopDbContextFactory` so migrations work without JWT settings.
- `GET /auth/me` is the protected endpoint; `AdminOnly` has no endpoint yet and is tested through `IAuthorizationService`.
- Login has no lockout or rate limiting yet, and an unknown email skips password hashing, so response time can reveal which emails exist.
- `POST /prices` answers 400 for missing or malformed fields, including amount and currency, and 422 only for a past `effectiveFrom`.
- Price amounts must be positive with at most 2 decimals and 16 integer digits; a CHECK enforces `Amount > 0` in the database.
- Currencies are validated against a fixed ISO 4217 list in Domain, because an append-only typo could not be corrected.
- `effectiveFrom` uses the same parser as `asOf`, so a value without an offset is UTC, not server local time.
- `isCurrent` resolves with the current time, like `GET /skus/{id}/price` without `asOf`.
- A price dated today at an hour already past is accepted and changes the price from that hour; existing orders keep their frozen price.
- Registration takes an `sp_getapplock` per normalized email inside its transaction, because concurrent Identity inserts for one email deadlocked and returned 500.
- Orders validate the raw request (1-20 lines, qty 1-50) and also cap merged quantities at 50 per SKU.
- A SKU without a current price makes `POST /orders` answer 422; mixed currencies are a domain error, also 422.
- An Idempotency-Key (max 100 chars) replays the original order even if the new body differs; replay answers 200.
- Stock is reserved per product in ascending product id so concurrent orders cannot deadlock on inventory rows.
- `EnableRetryOnFailure` is off; order writes still run inside the execution strategy so enabling it later is safe.
- Pay and cancel use a row version on Order and retry up to 3 times on a concurrent change, so concurrent cancels release stock once.
- Inventory is seeded by migration SQL for products without a row, with a Restock movement, so stock always equals the sum of movements.
- `InventoryMovements` are insert-only, enforced in `SaveChanges` and by a database trigger, like prices.
- `POST /orders` needs the Customer role (`CustomerOnly` policy); `GET /orders/{id}` also allows Admin; pay and cancel are owner-only.
